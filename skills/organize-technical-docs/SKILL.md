# 组织技术文档

先了解要覆盖的读者与任务，再盘点已有文档、目录约定和入口链接。确定哪些内容帮助读者理解系统，哪些供具体操作或随用随查。

1. 建立一条简明的阅读路径。总览说明背景、职责边界和关键模块，每个模块链接到细节。具体操作按场景放到操作手册，参数、接口字段和完整规则放到参考资料。
2. 为重复出现的事实或规则指定主要维护位置，从其他文档链接过去。相互矛盾的表述先核对实现或现有决定，无法确认时标明来源和疑点。
3. 沿用合适的目录、标题和命名约定。移动文件或改动标题时检查相对链接、锚点及外部引用。已有稳定链接且无法同步调用方时，考虑保留入口。

检查读者能否从首页找到常见任务的操作、从总览找到关键细节，也能从细节返回入口。交付更新后的导航或建议结构，列出待核实的内容。
