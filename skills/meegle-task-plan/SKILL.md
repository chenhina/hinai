# 飞书项目技术方案

把工作项、关联资料和仓库中的实现串起来，输出可用于评审的技术方案。此流程只读取项目资料和代码，并写入本地方案文件。

## 获取需求

1. 接受工作项数字 ID 或详情链接，可用 `--project-key <key>` 指定空间。支持 `/<project_key>/story/detail/<id>` 和 `/space/<project_key>/story/detail/<id>`，从 URL 路径取空间和 ID，忽略查询参数及片段。空间按显式参数、链接、当前仓库配置的顺序解析。仍缺少空间时，搜索可访问空间并核对工作项。若有多个候选且无法确认，向用户核实。
2. 使用已授权的 Meegle 连接，或已配置的 [Meegle CLI](https://www.npmjs.com/package/@lark-project/meegle)。CLI 可通过 `meegle project search` 查找空间，以及用 `meegle workitem get --project-key <key> --work-item-id <id>` 读取详情。需要自定义字段时，先用 `meegle inspect workitem.get` 检查参数，再查空间和工作项类型的字段元数据。
3. 提取标题、背景、功能点、验收口径及已有决策。将富文本转换成便于引用的内容，保留关键链接。存在时记录优先级和目标版本。用字段显示名或当前空间的字段配置识别“验收标准”“How to Demo”“对话记录”等自定义字段。
4. 通过已授权的飞书文档或多维表格工具读取与需求直接相关的链接，记录内容来源。若工作项无法读取，可基于用户提供的材料继续。标明影响方案的资料缺口、信息冲突和待确认事项。

## 阅读代码

从用户指定的仓库或当前仓库出发，用需求中的业务术语、接口名和数据字段定位实现。沿入口、业务逻辑和存储追踪当前数据流，核对调用方、数据结构、权限边界和相关测试。以仓库内相对路径引用关键文件，能定位时附行号。若代码缺失或关系尚未核实，在方案中标明影响和需补查的位置。

## 写入方案

围绕以下内容组织 Markdown。细节按需求规模取舍。

- **需求总结** 记录工作项链接或 ID、背景、范围、功能点和验收标准，区分已确认信息和待确认问题。
- **现状与数据流** 引用关键代码，说明现有行为以及方案会改变的数据流。
- **实施方案** 逐项列出目标模块、拟修改位置、预期行为和实施顺序。涉及接口或数据结构时，写明兼容性及迁移方式。代码片段用于澄清关键改动。
- **风险评估** 检查历史数据、误写或误删、数据正确性、并发、性能及接口权限。对适用项写明触发条件、影响和缓解方式，保留尚待验证的风险。
- **测试与验收** 将验收点映射到测试场景和可观察的预期结果，按改动补充异常路径、回归测试或迁移验证。

优先使用用户指定的输出位置，其次沿用仓库已有的方案目录，例如 `.vscode/task_plan/`。其余情况写到仓库根目录的 `task-plans/`。文件名用简短的小写连字符表示，如 `account-export-plan.md`，标题难以提取时可用 `story-<id>-plan.md`。同名文件属于同一工作项时保留已有的人工补充，属于其他工作项时用工作项 ID 区分。完成后返回文件路径和影响实施或验收的待确认事项。
