# 用运行证据改进 Skill

先定位目标 skill 和用户提供或授权查看的运行材料。记录原来的输入、预期行为、实际结果及可核实的偏差。区分触发不准、步骤遗漏、工具或权限缺失、输出要求含糊等原因。工具访问失败应按实际环境条件判断。

1. 提取必须保留的触发范围、用户约束、输入输出和外部操作边界。先把这次失误写成一个可复测场景，再选一个相近的正常场景保护既有行为。
2. 找到造成偏差的最小改动，例如把规则放在应该作决定的步骤前，补清判断条件，或集中维护重复规则。较大的重构按实际调用时机拆分，保留入口指引。
3. 用同一失败场景比较修改前后，再核对正常场景和受影响的约束。对已修改的脚本运行最相关的测试。无法重跑原场景时，说明实际验证了什么。

按用户要求给建议或修改目标 skill。总结证据、改动和复测结果，并记录仍需积累的证据。适合反复验证的场景可在用户要求时写入 `evals/`。保存可共享样例时使用脱敏摘要或合成输入。
