# 拆分大型 PR

确认要比较的 base、head 和仓库。PR 有行数限制时，查看仓库的检查脚本和计数范围，按对应规则报告结果。对本地分支明确比较区间，对 GitHub PR 则优先使用实际 PR 的基线。

1. 识别变更中可以独立解释的目标、先决条件和调用依赖。评估是否能将准备性重构、迁移、行为变化或机械改动分开。
2. 为每个子 PR 写明目的、主要改动、验证方式及依赖顺序。将测试放在它验证的行为附近。检查中间合并状态是否能构建、测试并保持运行兼容。
3. 对无法独立合并的部分标出原因，说明是否需要堆叠 PR 或兼容过渡。体量仍大时，优先保留行为的完整性，并解释为何该部分应一起评审。

默认交付拆分计划和每段的验证方式。用户要求实际拆分时，保护已有工作区改动并按目标顺序验证各分支。推送或创建 PR 的范围以用户授权为准。
