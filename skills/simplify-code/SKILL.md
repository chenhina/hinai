# 简化代码

先确认改动范围。用户未指定范围时，从当前变更涉及的代码着手，读取调用方、已有测试和同目录的实现习惯。

1. 写清必须保留的可观察行为，例如返回值及顺序、错误传播、默认值、副作用顺序和资源释放。合并相似分支前对照各分支触发条件与行为差异。
2. 优先消除不必要的嵌套、重复判断和间接转发。选择能直接体现业务含义的命名。只有当抽取能减少真正共享的复杂逻辑或明确责任边界时，才引入抽象。沿用当前项目的依赖与约定。
3. 审查差异，确认公开接口、边界输入和错误路径仍符合原约定。运行最相关的既有测试。若发现缺陷，记录它的影响，单独确定是否需要修复。

汇报做了哪些具体简化，以及用于验证行为的检查。
