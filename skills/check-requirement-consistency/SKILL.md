# 核对需求一致性

明确比较范围和阶段，记录每份资料的版本、状态和来源。设计阶段核对需求与当前可用的方案，实施后可以加入目标提交与测试。用已确认的需求或变更决定作为基线，遇到互相冲突的约定时标明待决项。

1. 将需求拆成可核对的行为。记录触发条件、操作者、可见结果和异常分支。保留已有需求 ID 或章节链接。
2. 逐条对照相关产物，按需要检查字段、权限、状态、计算规则、边界输入与测试断言。区分一致、描述冲突、遗漏或资料尚不可验证。计划明确为后续阶段的内容按当前阶段判断。
3. 对有差异的项引用双方证据，说明受影响的用户行为、实现或验收场景。针对已经确认的规则指出应补齐的产物。若需要选择产品行为，列出待决定的问题。

输出简表，包含需求锚点、已查产物、差异、影响和下一步。未读取的资料标记为未验证。
