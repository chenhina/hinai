# 评审代码变更

确认评审目标、base 和 head。PR 以描述和对应提交为准，用 GitHub 连接或 `gh pr view`、`gh pr diff` 获取资料。本地评审使用用户指定的范围。检查本地代码是否对应所评审的版本，再使用它定位行号。

1. 先明确变更要解决的问题、受影响的入口和已有的行为约定。阅读修改处的调用方及相关测试，必要时对照 base，确认问题是否由这次变更引入。
2. 按改动检查相关风险。状态写入关注异常恢复、幂等与并发，契约和数据变更关注已有调用方、旧数据及迁移，权限相关改动核对实际权限边界，界面改动检查关键流程和异常状态。
3. 逐条核实发现。读实现确认框架或辅助函数的语义，找出能触发问题的有效输入或运行条件，并说明实际影响。对缺少证据的判断，记录待确认的问题及所需证据。

先给出按影响排序的发现。每项引用变更位置、触发条件、具体后果和建议修法。若未发现需要修改的问题，直接说明，并记录会影响判断的验证缺口。只有用户要求发布评审时，才向远端提交评审或评论。
