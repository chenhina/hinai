# 仓库与 CI 检查

## 机器能确定的检查

| 检查项 | 判据 |
| --- | --- |
| 变更范围 | PR 使用与 base 的共同祖先到目标提交的差异。本地提交前可读暂存区。读取失败或基线缺失应返回错误。 |
| 文本和配置 | 校验约定的编码、行尾和末尾换行。用解析器检查配置语法、重复键和非标准值。必填字段、值域或跨文件关系按该项目的 schema 另行校验。 |
| 路径和产物 | 文件名限制按项目约定启用。对生成报告和缓存，通过忽略规则及已追踪文件检查确认提交范围。 |
| 规则与派生文件 | 为每条规则保留一个维护位置。生成 AI 指令或评审配置时保证输出稳定，在 CI 重新生成后比较指定产物的差异。 |

文本、严格 JSON 和可选路径检查可直接运行。 [脚本和用法](../scripts/README.md#check-repo-policypy)

## 需要项目配置的检查

- **依赖可复现。** 使用锁文件及对应的冻结安装方式。CI 动作、镜像和下载制品按其分发方式锁定提交、摘要或版本。下载制品执行前用预先固定的哈希或可信签名验证，校验失败时终止。
- **Lint 豁免可复核。** 记录被豁免的规则、原因和复查条件。项目采用到期日时，较早日期视为过期，并明确截止当天的行为。检查从语法中的实际注释提取指令，避免把字符串和示例当成豁免。
- **门禁反映实际结果。** 汇总每个必需检查的结果。失败、取消和意外跳过都应在门禁中可见。条件运行的检查要独立定义何时可以跳过，并区分故意跳过与前置失败导致的跳过。

引入阻断检查前，用合格和不合格样例核对结果。存量规则分批启用时，可先检查变更范围，并记录暂时豁免的范围和复查条件。
