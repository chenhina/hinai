# 代码评审规则

## 错误处理

- **处理有语义的返回值。** 检查写入、刷新、关闭写入流和事务提交失败时，调用方能否得知操作没有完成。尽力清理失败是否需要记录，取决于是否会留下资源、文件或不一致状态。
- **按语义识别错误。** Go 代码用 `errors.Is` 匹配已知错误，用 `errors.As` 取出错误类型。核对包装后是否仍可识别，以及调用方对重试、回退和失败终态的判断。
- **保留足够的安全上下文。** 错误、日志和告警只携带定位所需的字段。检查嵌套错误、完整 URL、请求体和响应体是否含令牌或敏感记录，必要时提取安全字段后再输出。

## 资源与持久化

- **明确资源由谁释放。** 获取成功后安排清理，检查提前返回、重试和所有权转移。循环中逐次释放短生命周期资源。测试 helper 把资源交给调用者时，清理应覆盖使用期，例如注册 `t.Cleanup`。
- **把数据写完再声明成功。** 检查暂存产物是否在刷新并关闭成功后才发布。需要替换旧文件时，确认所用存储支持期望的原子替换语义，并覆盖中途失败时的旧文件和临时文件状态。
- **参数化数据库输入并结束事务。** 参数值用查询参数绑定，动态标识符由受控集合选择。检查事务的提交、回滚和提交错误传播。已发布迁移采用新增迁移延续，按实际部署顺序验证新旧版本共存及中断恢复。

## 测试与告警

- **让测试独立并断言结果。** 检查成功与错误路径是否有可观察的断言。测试创建的数据、临时文件和替换的依赖由同一测试清理。共享状态需要隔离后再并行，测试替身应兑现依赖的接口行为和副作用。
- **为告警提供处理路径。** 新增告警时，从触发信号追到负责方、排查所需的字段和第一步处置。适合长期维护的步骤可链接到操作手册。按信号是否需要行动确定事件级别。
